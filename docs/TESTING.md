# Проверка подключения: Flowseal Standard

С версии 0.3.1 приложение использует набор проверок из `service.bat → Run tests → Standard`. Кнопка **Standard · Все штатные** соответствует выбору `All configs`: один проход по всем 22 BAT-стратегиям поставляемого комплекта, включая штатный EXP. Перед ними приложение дополнительно измеряет подключение без собственного движка. Шесть сгенерированных вариантов выбираются отдельно; автоматический подбор сравнивает все 28.

Эталоном послужил предоставленный комплект `zapret-discord-youtube-1.10.1`. В нём 21 BAT-файл; в закреплённой ревизии нашего комплекта — 22. Набор адресов и режимы перенесены из эталона, включая отсутствовавший ранее в нашем списке Quad9. Исходные скрипты не выполняются: Python управляет только собственными процессами.

## Почему старые 5/5 были недостаточны

Раньше проверялись главные страницы YouTube и Discord, JPEG-превью, YouTube oEmbed и REST `/api/v10/gateway`. Они могут отвечать, когда недоступны Googlevideo, непосредственный Discord Gateway, CDN или другой вариант TLS. Пять успешных запросов не означали полноценную работу сервисов.

Старые результаты не участвуют в выборе Standard. JSON новой проверки имеет `schemaVersion: 2` и `suiteId: flowseal-standard-v1`; у каждого результата есть режим, статус и номер повтора. Завершённость прежнего автоподбора сбрасывается при обновлении, но явная отмена пользователем сохраняется.

## Матрица одного прохода

| Группа | Адреса |
| --- | --- |
| Discord | discord.com, gateway.discord.gg, cdn.discordapp.com, updates.discord.com |
| YouTube | www.youtube.com, youtu.be, i.ytimg.com, redirector.googlevideo.com |
| Google | www.google.com, www.gstatic.com |
| Cloudflare | www.cloudflare.com, cdnjs.cloudflare.com |
| Только ping | 1.1.1.1, 1.0.0.1, 8.8.8.8, 8.8.4.4, 9.9.9.9 |

Каждый из 12 HTTPS-адресов получает:

1. `HTTP`: HEAD с `--http1.1` по HTTPS/TCP.
2. `TLS1.2`: HEAD с `--tlsv1.2 --tls-max 1.2`.
3. `TLS1.3`: HEAD с `--tlsv1.3 --tls-max 1.3`.
4. `PING`: три ICMP echo-запроса.

Дополнительные пять IP получают только ping. Итого: **36 HTTP/TLS-результатов и отдельно 17 ping-результатов**, то есть 53 записи на проход. Для двух повторов — 72 и 34 соответственно. Ожидаемое число фиксируется до начала прогона, частичный результат не становится полным из-за меньшего знаменателя.

Три HTTP/TLS-режима каждого хоста выполняются последовательно, до восьми хостов одновременно. Curl использует системное разрешение DNS и обычный выбор IPv4/IPv6; проверка обеих IP-семей по отдельности не выполняется. В TLS-колонках версия HTTP выбирается самим curl. Редиректы не обходятся. Общий таймаут каждого HEAD — пять секунд. Перед измерением запущенной стратегии даётся пять секунд на инициализацию.

Список читается из `bundle/utils/targets.txt`, формат `Имя = "https://адрес"` либо `Имя = "PING:IP"`. Допустимы комментарии `#`. Пустой, отсутствующий или некорректный файл останавливает проверку с объяснением; он не заменяется незаметно на укороченный список. Снимок целей сохраняется в отчёте и одинаков для baseline, кандидатов и повторного подтверждения.

## Что означают статусы

| Статус | Значение |
| --- | --- |
| OK | Curl успешно получил HTTP-ответ либо получены все три ICMP echo-ответа |
| ERROR | Таймаут, ошибка соединения/рукопожатия, сбой процесса или неполный ping |
| SSL | Ошибка DNS или сертификата — название категории сохранено из Standard |
| UNSUP | Curl явно сообщает об отсутствии возможности либо недоступен нужный инструмент |
| CANCELLED | Проверка отменена; результат не участвует в автоматическом выборе |

Как у Flowseal, HTTP 301, 403, 404 и 500 могут иметь статус **OK**, если curl успешно завершился: сервер ответил на HEAD. HTTP-код сохраняется и показывается в деталях. Это **не подтверждение доступа к содержимому**. ICMP-ответы DNS-сервера не проверяют DNS-запросы.

Сначала стратегии сортируются по количеству HTTP/TLS OK, затем по количеству успешных ping. Полное равенство разрешается стабильным порядком ID. Задержка отображается, но не определяет победителя. Ping никогда не прибавляется к HTTP/TLS-проценту. UNSUP всегда остаётся отдельным непроверенным результатом.

Автоприменение строже печати `Best config` в исходном скрипте: нужны полный набор результатов, улучшение относительно baseline, отсутствие ошибок в проверяемых HTTP/TLS-соединениях, неизменная сеть и независимый повторный прогон кандидата. Лучший частичный вариант можно выбрать вручную. Если baseline уже успешен, приложение сообщает только, что адреса отвечают; оно не утверждает, что обход не нужен.

Если curl явно не поддерживает TLS 1.3 на **всех** адресах и повторах, одинаково в baseline и у кандидата, для автоприменения допускается сравнение обязательных HTTP/1.1 и TLS 1.2. Счётчик при этом остаётся **24/36 и 12 UNSUP**, а не 100%; непроверенный режим указан в объяснении. Неподдерживаемость только части адресов, изменение набора UNSUP или ошибка рукопожатия под это исключение не подходят.

## Осознанные отличия от PowerShell-скрипта

- Не завершаются чужие процессы winws. При конфликте перебор блокируется. BAT и штатный `test zapret.ps1` не запускаются.
- До перебора добавлен baseline, затем независимое подтверждение кандидата. Штатный Standard только печатает лучшую конфигурацию; наша автоматизация применяет её лишь после проверки.
- Для воспроизводимости отключены `.curlrc` и прокси из окружения (`--disable --noproxy *`). Системный VPN всё равно влияет на маршрут.
- Ошибка curl 35 или слово `schannel` сами по себе не означают UNSUP: ошибка TLS-рукопожатия остаётся ошибкой, пока нет явного сообщения о неподдерживаемой возможности.
- Ping запускается без PowerShell: три запроса, до 1000 мс ожидания ответа на каждый, до восьми секунд на весь процесс. Локализованный текст «узел недоступен» и код выхода 0 не принимаются за успешный echo-ответ.
- Нет общего 10-секундного обрыва runspace, способного усечь три запроса по пять секунд. Каждый дочерний процесс имеет собственный ограниченный срок и останавливается при отмене.
- Ошибка запуска или завершение движка во время теста исключает кандидат. Неполные матрицы и дубли не дают успешного результата.

## Пределы Standard

Даже 36 HTTP/TLS OK и 17 ping OK **не доказывают работу YouTube и Discord целиком**. Googlevideo проверяется только HEAD-запросом к redirector, а не загрузкой `/videoplayback` с конкретного видеосервера. Discord Gateway проверяется по HTTPS, без WebSocket upgrade, авторизации и голосового соединения. QUIC, UDP-голос, скорость воспроизведения и перемотка требуют отдельной проверки в приложениях. Режим upstream `DPI checkers (TCP 16–20)` — другой тест и в Standard не включён.
