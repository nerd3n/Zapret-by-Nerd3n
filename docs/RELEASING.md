# Как собрать и опубликовать релиз

Этот документ описывает выпуск **zapret by nerd3n 0.3.7** для Windows 10/11 x64:
сборку из конкретного коммита, проверку, подготовку архивов и ручную публикацию
на GitHub. Команды выполняются в PowerShell. Публикация начинается только на
последнем этапе; компиляция сама ничего не устанавливает и не запускает winws.

Репозиторий: [nerd-en/zapret-by-nerd3n](https://github.com/nerd-en/zapret-by-nerd3n).
Тег выпуска: `v0.3.7`. Для этого выпуска рекомендуется отметка **Pre-release**:
сохранение диагностики запуска нужно проверить перед публикацией,
а эффективность стратегий на реальной линии **Инфолинк, Щёлково** ещё не подтверждена.
Версия 0.3.7 улучшает диагностику немедленного выхода `winws`. Не описывайте её
как исправление кода 2: сообщённый сбой не воспроизведён, прежний вывод процесса
не был сохранён.

## Что потребуется

| Компонент | Версия и назначение |
| --- | --- |
| Windows | Windows 10/11 x64. ARM64 не поддерживается поставленным драйвером. |
| Python x64 | Исходный код требует Python 3.10+. Для повторения процедуры сборки используйте Python **3.13.5 x64**. |
| PyInstaller | **6.22.3**, установленный в отдельное виртуальное окружение. |
| Inno Setup | **6.7.3**, нужен `ISCC.exe`. Установленный компилятор или официальный portable-режим. |
| pywebview | **6.2.1**, зависимости из `requirements.txt`; для запуска окна нужен WebView2 Runtime x64. |
| Git | Для фиксации исходников и создания архива конкретного коммита. |
| GitHub Desktop | Необязательно; удобен для commit/push без терминала. |
| GitHub CLI | Необязательно; веб-интерфейса GitHub достаточно для публикации. |

Пользователю готового EXE Python, PyInstaller и Inno Setup не нужны. Системный
`curl.exe` нужен приложению для сетевых проверок. GSAP 3.15.0 уже находится в
`web/vendor`; npm для сборки этой версии не требуется.

Версии инструментов и зависимостей закреплены для повторения процедуры. Это
не обещание побайтово одинаковых EXE: на результат также влияют Python, Windows,
временные метки и среда сборки. Для каждого нового набора артефактов вычисляйте
собственные контрольные суммы.

## 1. Подготовить версию и исходники

Работайте из корня репозитория; замените путь на свою папку:

```powershell
Set-Location -LiteralPath 'C:\Projects\zapret-by-nerd3n'
git status --short
git branch --show-current
git remote -v
```

Ожидаемая ветка — `main`, origin —
`https://github.com/nerd-en/zapret-by-nerd3n.git`.

Проверьте согласованность номера версии:

| Файл | Что проверить |
| --- | --- |
| `zapret_ui/__init__.py` | `__version__ = "0.3.7"` |
| `app-version.txt` | `FileVersion` и `ProductVersion` — `0.3.7`, числовые поля — `(0, 3, 7, 0)` |
| `installer/ZapretByNerd3n.iss` | `AppVersion` по умолчанию — `0.3.7` |
| `installer/build-installer.ps1` | `$Version` по умолчанию — `0.3.7` |
| `README.md`, `docs/RELEASE_NOTES-v0.3.7.md`, `VERIFICATION.md` | Возможности, результаты и ограничения соответствуют выпуску; невыполненные проверки не отмечены как успешные |

MIT-лицензия приложения соответствует типу лицензии Flowseal. Сохраняйте
авторство nerd3n, оригинальный `bundle/LICENSE.txt` и отдельные условия
сторонних компонентов: `THIRD_PARTY.md`, `GSAP-LICENSE.txt`, `PYTHON-LICENSE.txt`, `DESKTOP-LICENSES.txt`.
MIT оболочки не меняет лицензии WinDivert, Cygwin и GSAP.

Не добавляйте в Git:

- `data/`: настройки, отчёты, локальный ключ и сведения о проверенном подключении;
- `bundle/lists/*-user.txt`, результаты штатных тестов и локальные логи;
- `__pycache__/`, `*.pyc`, виртуальное окружение, `build/`, `dist/`;
- собранные `ZapretByNerd3n.exe`, установщик и релизные ZIP;
- `environment-check.json`, `.env`, ключи, токены и другие личные файлы.

Проверьте изменения внутри `bundle`: пользовательская замена `ACTIVE_*.bin`
или списков не должна случайно стать штатной конфигурацией выпуска. Движок,
списки и стратегии из выбранной ревизии upstream входят в исходный репозиторий
и поставку намеренно; их происхождение описано в `THIRD_PARTY.md`.

## 2. Проверить код и зафиксировать коммит

Для автоматических тестов сторонние Python-пакеты не требуются:

```powershell
py -3.13 -m unittest discover -s tests -v
```

Для регрессионных проверок интерфейса нужен Node.js; сторонние npm-пакеты не требуются:

```powershell
node --test tests/test_frontend_standard.js
```

Ожидаются успешные тесты; в среде без права создания символьных ссылок допустим
пропуск соответствующего теста. Актуальное число тестов смотрите в выводе,
а не используйте старое число как критерий успеха. Тест Windows Job Object
запускает и завершает только собственные безвредные Python-процессы. Тесты
сетевой логики используют подставные ответы; они не подтверждают обход DPI.

Для проверки окна сначала создайте локальное окружение и установите зависимости.
Эта команда запускает интерфейс без стартового определения сети и перебора стратегий:

```powershell
py -3.13 -m venv .venv
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать окружение проверки' }
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
if ($LASTEXITCODE -ne 0) { throw 'Не удалось установить зависимости окна' }
& .\.venv\Scripts\python.exe main.py --no-auto-setup --port 17842
```

Откроется отдельное окно приложения. Не нажимайте запуск стратегий или определение сети,
если выполняете только проверку UI. Для выхода используйте **Завершить приложение**.
Закрытие окна завершает сеансовый движок и сервер; установленная служба продолжает работать.

После проверок сделайте локальный commit. Через GitHub Desktop:

1. **File → Add local repository**: выберите папку проекта и добавьте её.
2. Убедитесь, что выбраны нужный репозиторий и ветка `main`.
3. В **Changes** просмотрите список файлов и diff; личные файлы и сборки туда попадать не должны.
4. Введите Summary, например `Prepare zapret by nerd3n 0.3.7`, и нажмите **Commit to main**.
5. Push можно выполнить после проверки получившихся артефактов, как описано ниже.

Добавление локального репозитория описано в
[документации GitHub Desktop](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop).
Все следующие артефакты строятся из **этого зафиксированного коммита**, а не из
незакоммиченных файлов рабочей папки.

## 3. Создать чистый снимок и исходный ZIP

Следующий блок создаёт новую папку внутри игнорируемого `dist`. Старые сборки
и пользовательские данные не удаляются.

```powershell
$repo = (Get-Location).Path
$version = '0.3.7'
$commit = (git rev-parse HEAD).Trim()
if ($LASTEXITCODE -ne 0) { throw 'Не удалось получить коммит' }
if (git status --porcelain) { throw 'Сначала зафиксируйте или отдельно сохраните изменения' }

$forbidden = git ls-files | Where-Object {
    $_ -match '(^|/)(data|__pycache__|\.venv|\.build-env|build|dist|release-assets)(/|$)' -or
    $_ -match '\.py[co]$|(^|/)\.env($|\.)|(^|/)environment-check\.json$' -or
    $_ -match '^bundle/lists/.*-user\.txt$|^bundle/utils/(test results|logs)/' -or
    $_ -match '^bundle/.*\.(log|backup|test-backup\.txt)$|^bundle/utils/game_filter\.enabled$' -or
    $_ -match '(^|/)(ZapretByNerd3n|Zapret-by-nerd3n-Setup)\.exe$'
}
if ($forbidden) {
    $forbidden
    throw 'В Git уже отслеживаются файлы, не предназначенные для выпуска'
}

$releaseRoot = Join-Path $repo ('dist\release-' + $version + '-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $releaseRoot | Out-Null
$sourceZip = Join-Path $releaseRoot 'zapret-by-nerd3n-source.zip'
git archive --format=zip --prefix=zapret-by-nerd3n-source/ "--output=$sourceZip" $commit
if ($LASTEXITCODE -ne 0) { throw 'Не удалось собрать архив исходников' }
Expand-Archive -LiteralPath $sourceZip -DestinationPath (Join-Path $releaseRoot 'source')
$sourceRoot = Join-Path $releaseRoot 'source\zapret-by-nerd3n-source'
```

`git archive` включает отслеживаемые файлы выбранного коммита и не включает
локальные `data/`, кэши и окружение, если они не были добавлены в Git. ZIP
исходников содержит код оболочки, тесты, документацию, интерфейс, профиль и
комплект upstream. Он не содержит собранный EXE оболочки.

## 4. Собрать приложение

Продолжайте в том же PowerShell-окне, чтобы сохранить значения переменных:

```powershell
$venvRoot = Join-Path $releaseRoot 'build-env'
py -3.13 -m venv $venvRoot
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать окружение' }
$buildPython = Join-Path $venvRoot 'Scripts\python.exe'
& $buildPython -c 'import sys, struct; print(sys.version); print("bits:", struct.calcsize("P") * 8)'

& $buildPython -m pip install `
    'pyinstaller==6.22.3' `
    'pyinstaller-hooks-contrib==2026.7' `
    'altgraph==0.17.5' `
    'packaging==26.3' `
    'pefile==2024.8.26' `
    'pywin32-ctypes==0.2.3' `
    'setuptools==84.0.0'
if ($LASTEXITCODE -ne 0) { throw 'Не удалось установить инструменты сборки' }
& $buildPython -m pip install -r (Join-Path $sourceRoot 'requirements.txt')
if ($LASTEXITCODE -ne 0) { throw 'Не удалось установить зависимости окна' }

Push-Location -LiteralPath $sourceRoot
try {
    & $buildPython -m unittest discover -s tests -v
    if ($LASTEXITCODE -ne 0) { throw 'Тесты снимка исходников не прошли' }

    & .\tools\build-desktop.ps1 -BuildPython $buildPython
} finally {
    Pop-Location
}
```

Проверьте, что вывод Python сообщает 64 бита. `tools/build-desktop.ps1` создаёт
`build/desktop/payload.zip` из комплекта чистого снимка и встраивает его в EXE
вместе с `web`. Архив содержит `bundle` с движком, DLL, драйвером, стратегиями,
списками и утилитами, `profiles` и `licenses`. В `licenses` входят `LICENSE`,
`THIRD_PARTY.md`, `PYTHON-LICENSE.txt`, `GSAP-LICENSE.txt` и `DESKTOP-LICENSES.txt`;
оригинальная лицензия комплекта также остаётся в `bundle/LICENSE.txt`.
Пользовательские файлы, настройки и отчёты не должны попадать во встроенный архив.

Результат по умолчанию — `dist/ZapretByNerd3n.exe` и его файл SHA-256. Скрипт
также копирует EXE в корень снимка для Inno. Доступен параметр `-OutputDir`.
Используйте этот helper вместо прежней команды PyInstaller только с `--add-data web`:
без встроенного payload отдельный EXE не сможет подготовить движок на новом ПК.
Флаг `--uac-admin` не нужен:
повышением прав управляет аргумент приложения `--elevate`, который уже прописан
в установленном ярлыке. Параметры PyInstaller описаны в
[официальной документации](https://pyinstaller.org/en/stable/usage.html).

Значок EXE и установщика берётся из `assets/app.ico`, логотип интерфейса —
из `web/assets/logo.png`, favicon — из `web/favicon.ico`. Окно pywebview
получает локальную ICO-иконку явно; процесс устанавливает `AppUserModelID`
`Nerd3n.Zapret`, совпадающий с ярлыками приложения. В `[Icons]` установщика
источник значка указан явно: `IconFilename` ведёт к EXE, `IconIndex` равен 0.
Проверяйте комплектность `web` и наличие `assets/app.ico` при подготовке пакета.

Флаг `--noupx` исключает влияние случайно установленного UPX. Ранее созданный
локальный `.spec` с абсолютными путями не требуется: он генерируется заново.

## 5. Подготовить переносную папку и установщик

Копируется только известный состав поставки из чистого снимка:

```powershell
$portableRoot = Join-Path $releaseRoot 'portable\zapret-by-nerd3n'
New-Item -ItemType Directory -Path $portableRoot | Out-Null
Copy-Item -LiteralPath (Join-Path $sourceRoot 'dist\ZapretByNerd3n.exe') -Destination $portableRoot
Copy-Item -LiteralPath (Join-Path $sourceRoot 'dist\ZapretByNerd3n.exe') -Destination (Join-Path $releaseRoot 'ZapretByNerd3n.exe')

foreach ($folder in @('bundle', 'profiles', 'docs', 'assets')) {
    Copy-Item -LiteralPath (Join-Path $sourceRoot $folder) -Destination $portableRoot -Recurse
}
foreach ($document in @('README.md', 'LICENSE', 'THIRD_PARTY.md', 'PYTHON-LICENSE.txt', 'GSAP-LICENSE.txt', 'DESKTOP-LICENSES.txt', 'VERIFICATION.md')) {
    Copy-Item -LiteralPath (Join-Path $sourceRoot $document) -Destination $portableRoot
}

$iscc = 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
& (Join-Path $sourceRoot 'installer\build-installer.ps1') `
    -AppDir $portableRoot -CompilerPath $iscc -OutputDir $releaseRoot -Version $version
```

Если Inno Setup расположен иначе, измените только `$iscc`. Используйте официальный
[Inno Setup 6.7.3](https://github.com/jrsoftware/issrc/releases/tag/is-6_7_3).
Скрипт проверяет обязательные файлы, компилирует установщик и пишет
`Zapret-by-nerd3n-Setup.exe.sha256`. Он не запускает установку.

Отдельный `ZapretByNerd3n.exe` в `$releaseRoot` — самостоятельный файл для Release
assets. Пользователь может положить его в пустую доступную для записи папку:
обычный запуск создаёт рядом отсутствующие `bundle`, `profiles` и `licenses`.
Распаковка использует встроенные данные, без скачивания движка. Повторный запуск
не перезаписывает существующие файлы. Замена только EXE поэтому не обновляет уже
существующий `bundle`; штатные файлы комплекта обновляет установщик с сохранением
пользовательских списков и `ACTIVE_*.bin`.

Установщик содержит весь необходимый комплект и профиль
`profiles/infolink-shchelkovo.json`; пользователь не выбирает папку внешнего zapret.
Установка предназначена для текущего пользователя, путь по умолчанию —
`%LOCALAPPDATA%\ZapretByNerd3n`. Обычный ярлык вызывает `--auto --elevate`,
запуск после установки — `--auto` через UAC. Отмена UAC не отменяет установку.
Установка приложения сама не создаёт службу. Пользователь устанавливает её кнопкой «Установить с автозапуском» внутри приложения; тогда движок запускается при старте Windows. Деинсталлятор удаляет нашу службу отдельным вызовом EXE `--remove-service` с UAC; при отказе UAC или если служба осталась зарегистрирована, отменяет удаление приложения.

Чтобы получить portable ZIP без потери файлов с именами, начинающимися с точки:

```powershell
$portableZip = Join-Path $releaseRoot 'zapret-by-nerd3n-portable.zip'
@'
from pathlib import Path
from zipfile import ZipFile, ZIP_DEFLATED
import sys
root = Path(sys.argv[1]).resolve()
with ZipFile(sys.argv[2], "w", ZIP_DEFLATED, compresslevel=9) as archive:
    for path in sorted(root.rglob("*")):
        if path.is_file():
            archive.write(path, path.relative_to(root.parent).as_posix())
'@ | & $buildPython - $portableRoot $portableZip
if ($LASTEXITCODE -ne 0) { throw 'Не удалось собрать переносной архив' }
```

Создавайте архив из этой подготовленной папки **до обычного запуска приложения**.
Даже запуск с `--no-auto-setup` создаёт `data/` и отсутствующие пользовательские
списки. Для проверки готового EXE распакуйте portable ZIP в отдельную тестовую
папку, запустите оттуда `ZapretByNerd3n.exe --no-auto-setup --port 17842` и
завершите через интерфейс. Не упаковывайте эту тестовую папку обратно в релиз.
Portable ZIP остаётся дополнительным вариантом с заранее разложенными файлами;
для скачивания и первого запуска достаточно отдельного EXE.

## 6. Проверить состав, ограничения и SHA-256

Проверьте оба ZIP: отсутствуют `data`, пользовательские списки, кэши, локальные
логи, `.git` и виртуальные окружения. Исходный ZIP содержит исходники и тесты;
portable ZIP — EXE, bundle, профиль и документы. Не публикуйте `environment-check.json`.
Отдельно проверьте содержимое встроенного `payload.zip` по тем же правилам.

Перед каждым выпуском проверьте интерфейс, отмену автоподбора и штатный выход.
Реальную установку/удаление желательно отдельно проверить на тестовом Windows-ПК.
Если этого не делали, прямо укажите это в описании выпуска. Сборка установщика
не равна проверке установки.

### Проверка диагностики запуска в 0.3.7

Перед публикацией проверьте, что при немедленном завершении созданного сеансового
процесса сообщение содержит его код выхода и последний фрагмент его же вывода.
В `data/last-startup-failure.json` должны сохраниться версия, стратегия, PID,
аргументы, рабочая папка, вывод и признаки его усечения или незавершённого чтения.
После закрытия окна файл должен остаться; следующий такой сбой заменяет предыдущую
запись. Ошибка сохранения должна быть видна пользователю и не скрывать исходный сбой.

Проверки с подставным процессом подтверждают сбор диагностики, но не воспроизводят
причину пользовательского кода 2. Не публикуйте локальные диагностические JSON
или всю папку `data` в артефактах. Фактические результаты и число тестов нового
выпуска внесите в `VERIFICATION.md` после прогона.

### Регрессия отдельного EXE из 0.3.6

Это план проверок, а не результаты. Используйте отдельную папку с правом записи
и свободный порт. Для проверки извлечения достаточно `--no-auto-setup`; запускать
стратегию или устанавливать службу для этого не требуется.

| Сценарий | Что проверить |
| --- | --- |
| В пустую папку скопирован только `ZapretByNerd3n.exe` | Окно открывается, рядом появляются `bundle`, `profiles`, `licenses` и рабочая `data`; каталог стратегий доступен без выбора пути и скачивания движка. |
| Обычный повторный запуск | Уже существующие файлы не меняются. Проверить SHA-256 выбранных `ACTIVE_*.bin`, пользовательского списка и изменённого штатного файла. |
| Один штатный файл отсутствует | Он восстанавливается из EXE; соседние существующие файлы остаются прежними. Проверку выполнять при закрытом приложении и без сеансового движка. |
| Нет права записи в папку назначения | Показывается понятная ошибка подготовки комплекта; программа не требует найти другую установленную копию zapret. |
| `--prepare-update` и `--remove-service` | Служебные ветки завершаются до извлечения payload и не создают рядом с временным EXE файлы комплекта или окно. Удаление службы проверять только на выделенном тестовом ПК. |
| Открытие и закрытие обычного окна | Состояние существующей службы не меняется; если службы не было, она не появляется. |
| Запуск исходников через `main.py` | Используется `bundle` репозитория; встроенный архив не требуется. |

Записывайте фактические результаты в `VERIFICATION.md`. Не обещайте отсутствие
распаковки на диск: отдельный EXE содержит поставку, а движок работает из файлов
`bundle` рядом с ним. Папка службы остаётся отдельной защищённой копией.

### Проверка значков

### Регрессия исправления службы из 0.3.4

На целевом ПК прежняя установка службы ALT11 записала команду длиной 8216
кодовых единиц UTF-16: 16 432 байта только для `ImagePath`, без остальных полей
ответа. `QueryServiceConfigW` запросил 16 598 байт, но этот API допускает буфер
не больше 8 КБ. Вызовы с допустимым размером возвращали RPC 1734, с большим —
RPC 1783. Поэтому чтение созданной службы и последующий откат завершались ошибкой.
Ограничение указано в [документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryserviceconfigw).

Служба сохраняет прямой запуск `winws.exe` с полной командой `ImagePath`.
Параметры берутся из проверенного каталога стратегий и указывают на защищённую
копию в Program Files. Исправление не меняет формат запуска или выбранную стратегию.
Ограничение 8 КБ относится к чтению конфигурации через SCM, а не к допустимой
длине команды создания процесса, которая проверяется отдельно.

Только при известных ошибках RPC 1734/1783 либо `ERROR_INSUFFICIENT_BUFFER` (122)
с запрошенным размером больше 8192 байт конфигурация читается из реестра.
Резервный путь выполняет только чтение и требует защищённого ACL ключа,
ownership marker со схемой 1 и совпадения хеша команды. Текущее состояние и PID
всегда запрашиваются через SCM. **Запустить службу** запускает принадлежащую
приложению остановленную службу с сохранённой командой. После перехода в running
дополнительная проверка в течение 3 секунд выявляет немедленный выход процесса.

Перед публикацией выполните и запишите в `VERIFICATION.md`:

| Сценарий | Что проверить |
| --- | --- |
| Новая установка службы ALT11 | Полная команда соответствует стратегии; конфигурация читается через проверенный резервный путь, а running и PID — через SCM. |
| Короткая команда, помещающаяся в ответ 8 КБ | Конфигурация читается штатным `QueryServiceConfigW` без обращения к резервному пути. |
| Другие штатные и дополнительные стратегии | Команда сохраняет границы аргументов, значения, пути с пробелами и национальными символами. |
| Старая остановленная наша служба с ошибкой 1734/1783 либо ошибкой 122 и необходимым буфером больше 8 КБ | Чтение не меняет реестр; **Запустить службу** запускает ту же полную команду. |
| Чужой marker, другая схема, изменённая команда, небезопасный ACL или другая ошибка SCM | Резервное чтение не разрешает управление службой; операция завершается ошибкой. |
| Служба сообщает running и сразу завершается | Проверка устойчивости в течение 3 секунд возвращает ошибку, а не успешный результат установки или запуска. |
| Ошибка создания или запуска службы | Отображается причина; незавершённая операция не удаляет чужие данные и не теряет нужную для оставшейся службы копию. |
| Перезапуск приложения и отдельная перезагрузка Windows | Служба не зависит от окна, её состояние читается; автозапуск после reboot подтверждается только отдельным фактическим тестом. |

На проверенном ПК подтверждён запуск ALT11 с исходной полной командой,
автоматическим типом запуска и проверенной принадлежностью приложению.
Установленная копия обновлена с 0.3.3 до 0.3.4; 12 проверенных пользовательских
файлов сохранили прежние SHA-256. Процесс службы не перезапустился при обновлении,
открытии и закрытии окна. Автозапуск после перезагрузки ещё требует отдельной
проверки. Таблица выше остаётся планом остальных проверок; unit-тесты не заменяют
фактическую проверку соответствующего сценария.

### Регрессия исправления обновления из 0.3.3

В разобранном журнале обновление блокировала работающая версия 0.2.0: её EXE
был запущен с повышенными правами, Restart Manager обычного установщика получил
отказ в доступе, а замена файла завершилась ошибкой `DeleteFile`, код 5.

Новый установщик на этапе `PrepareToInstall` запускает вспомогательный режим
нового EXE из временной папки. Он проверяет принадлежность найденной запущенной
копии выбранной папке, вызывает её локальный `/api/exit` и ждёт освобождения
EXE и заменяемых файлов движка до 60 секунд. Подготовка выполняется до замены
файлов; блокировка или отказ в доступе должны остановить установку с объяснением.
Отдельное повышение прав для этого шага не требуется. Чужие процессы `winws`
и службы не останавливаются, существующая копия службы в Program Files не обновляется.

На целевой установке обнаружилась дополнительная причина отказа 0.3.2:
после штатного выхода приложения и `winws` Windows продолжала удерживать
`bundle/bin/WinDivert64.sys` (ошибка совместного доступа, код 32). Хеш установленного
драйвера совпал с новой поставкой, поэтому в 0.3.3 заменять его не требуется.
Helper и Inno пропускают **только этот файл и только при совпадении SHA-256**.
Ожидаемый хеш вычисляет ISPP `GetSHA256OfFile` из файла пакета при компиляции.
Не подменяйте эту проверку флагом `onlyifdoesntexist`, одинаковой версией ресурса
или исключением для всех SYS: изменённый файл должен пройти обычную подготовку
к замене. Ошибка чтения хеша не разрешает пропуск. Общую службу WinDivert
останавливать или удалять в ходе обновления не нужно.

Перед публикацией выполните на выделенном Windows-ПК или VM следующие сценарии
и запишите фактический результат каждого в `VERIFICATION.md`:

| Сценарий | Что проверить |
| --- | --- |
| Работающая 0.2.0 с повышенными правами, установщик 0.3.7 с обычными правами | Приложение штатно завершается; затем заменяется EXE. Подготовка не вызывает новый UAC. |
| Приложение на нестандартном порту, например `--port 17842` | Завершается именно копия из выбранной папки; поиск не ограничен портом 17841. |
| Другая копия приложения из иной папки | Она остаётся работать; установщик не отправляет ей команду завершения. |
| EXE или DLL остаётся занят либо доступ запрещён | По истечении ожидания установка останавливается до копирования; прежние установленные файлы не заменены. |
| После выхода приложения загруженный `WinDivert64.sys` остаётся занят, его SHA-256 совпадает с пакетом | Обновление не пытается переписать SYS и завершается; хеш драйвера и состояние общей службы сохраняются. |
| Занятый `WinDivert64.sys` отличается от файла пакета либо недоступен для проверки хеша | Исключение не применяется, установка останавливается до копирования; драйвер не останавливается и не удаляется. |
| Другой занятый EXE, DLL или SYS совпадает по хешу с поставкой | Исключение для WinDivert не распространяется на этот файл; проверка блокировки остаётся. |
| Настройки, отчёты, `*-user.txt` и выбранные `ACTIVE_*.bin` уже существуют | Данные сохранены после обновления; подготовка не сбрасывает профиль и списки. |
| Новая установка в пустую папку | Отсутствие прежнего EXE не считается ошибкой; после установки доступен обычный запуск. |

Работающая наша служба использует защищённый snapshot вне папки UI. Для
обновления оболочки её останавливать не требуется. Если сторонний процесс
или старая служба удерживает заменяемый файл внутри обновляемой папки, ожидается
отказ с объяснением, а не принудительное завершение этого процесса. Единственное
исключение — сохранение идентичного `WinDivert64.sys`, который вообще не заменяется.

Это план проверки, а не перечень уже выполненных действий. Проверка причины
по старому журналу, успешные тесты helper и компиляция Inno сами по себе не
подтверждают обновление поверх реальной работающей установки. Если такой
сценарий ещё не проверен, сохраните это ограничение в описании выпуска.

Сетевой прогон на линии Инфолинка проводится отдельно с разрешением владельца
подключения. Успешные HTTPS-проверки не доказывают воспроизведение видеопотока,
QUIC, WebSocket или голосовой UDP Discord. Не устанавливайте в профиле
`providerVerified`/`strategyVerified` в `true` без фактической проверки.

После окончательной сборки сформируйте контрольные суммы:

```powershell
$assetNames = @(
    'ZapretByNerd3n.exe',
    'Zapret-by-nerd3n-Setup.exe',
    'zapret-by-nerd3n-portable.zip',
    'zapret-by-nerd3n-source.zip'
)
$checksumLines = foreach ($name in $assetNames) {
    $hash = (Get-FileHash -LiteralPath (Join-Path $releaseRoot $name) -Algorithm SHA256).Hash.ToLowerInvariant()
    "$hash  $name"
}
[System.IO.File]::WriteAllLines((Join-Path $releaseRoot 'SHA256SUMS.txt'), $checksumLines, [System.Text.Encoding]::ASCII)

@("Version: $version", "Commit: $commit", 'Inno Setup: 6.7.3') |
    Set-Content -LiteralPath (Join-Path $releaseRoot 'BUILDINFO.txt') -Encoding UTF8
& $buildPython --version | Add-Content -LiteralPath (Join-Path $releaseRoot 'BUILDINFO.txt')
& $buildPython -m pip freeze | Add-Content -LiteralPath (Join-Path $releaseRoot 'BUILDINFO.txt')
```

После изменения хотя бы одного файла пересоберите соответствующий архив или
установщик и пересчитайте суммы. `SHA256SUMS.txt` помогает обнаружить повреждение
или замену файла; он не является цифровой подписью. Эта сборка EXE и установщика
не подписана сертификатом издателя.

## 7. Отправить main и создать GitHub Release вручную

В GitHub Desktop нажмите **Push origin** для ранее созданного коммита `main`.
Откройте репозиторий на GitHub и убедитесь, что последний коммит совпадает с
`$commit`. Если после сборки код изменился, соберите артефакты из нового коммита. Перед публикацией проверьте закрытие окна, скачивание отчёта и управление своей службой на отдельном тестовом ПК; не выдавайте тесты с подставным SCM за проверку после перезагрузки.
EXE и ZIP размещайте в **Release assets**, исходники — в дереве репозитория.

На [странице Releases](https://github.com/nerd-en/zapret-by-nerd3n/releases):

1. Нажмите **Draft a new release**.
2. В **Choose a tag** создайте `v0.3.7`; Target — `main` с проверенным коммитом.
3. Название: `zapret by nerd3n 0.3.7`.
4. Добавьте описание возможностей, требований и известных ограничений.
5. Прикрепите отдельный `ZapretByNerd3n.exe`, установщик, portable ZIP, source ZIP и `SHA256SUMS.txt`; при желании — `BUILDINFO.txt`.
6. Включите **This is a pre-release**. Сначала нажмите **Save draft**, проверьте состав, затем **Publish release**.

Порядок соответствует
[официальной инструкции GitHub](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).
Автоматические GitHub-архивы `Source code (zip/tar.gz)` формируются по тегу;
отдельный source ZIP нужен для явно подготовленного именованного комплекта.

Готовый текст для копирования находится в [RELEASE_NOTES-v0.3.7.md](RELEASE_NOTES-v0.3.7.md). Краткий пример:
