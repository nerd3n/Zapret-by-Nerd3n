# Проверка zapret by nerd3n 0.3.8

## Перенос проекта и обновление IPSet в 0.3.8

3 октября 2026 года проект перенесён в `nerd3n/Zapret-by-Nerd3n` с сохранением
истории исходного репозитория. Локальные настройки и данные скопированы с
проверкой SHA-256 и исключены из исходников и релизных архивов.

Комплект сверён с Flowseal `eb16c1419057e36b8a36fbe7c959483450e6ac8b`.
Обновлён только служебный IPSet из коммита `249a70424aae2676f99c5363e21073ed89873eda`:
33 048 строк, SHA-256 `c39bf4e1b151c7d0d42fe7dae4c09e01ac26806a1ff4060ae456c7fb22087651`.
Движок, DLL, драйвер и все 22 штатные стратегии совпадают с upstream.

Автоматические проверки 0.3.8: 325 Python-тестов за 11,855 секунды,
321 успешен, 4 пропущены из-за ограничения Windows на создание символических
ссылок; все 18 JavaScript-тестов успешны. Реальный обход DPI, установка и
обновление установленной программы в этом выпуске отдельно не проверялись.

Готовые артефакты должны дополнительно пройти проверку распаковки, версии,
каталога стратегий и штатного выхода; результат и SHA-256 фиксируются в
релизном `BUILDINFO.txt`. На момент фиксации исходников эта проверка ещё
не выполнялась.
Ниже сохранены результаты прежних выпусков с их исходными номерами версий.

Дата: 22 сентября 2026 года. Проверка приложения и проверка обхода в сети провайдера — разные результаты.

## Диагностика запуска в 0.3.7

Пользователь сообщил немедленное завершение `winws` с кодом 2. Вывод того процесса не сохранился; причина сбоя пока не воспроизведена. Новая версия добавляет последний фрагмент вывода конкретного процесса в ошибку и сохраняет сведения в `data/last-startup-failure.json`. Это изменение диагностики, не подтверждённое исправление причины кода 2.

При разборе сообщения выполнены отдельные проверки:

- 56 запусков `winws --dry-run`: 28 наборов аргументов установленного комплекта и 28 наборов отдельной распакованной копии; все завершились с кодом 0. `__COMPAT_LAYER=RunAsInvoker` был задан только дочерним проверочным процессам. `--dry-run` проверял разбор аргументов без запуска перехвата трафика.
- Отдельный вызов `WinDivertOpen` с повышенными правами, фильтром `false` и флагом sniff вернул действительный дескриптор; дескриптор закрыт. Проверка не перехватывала пакеты и не измеряла обход DPI.
- Настоящий `winws` запущен с аргументами ALT11 и полным переопределением фильтра через `--wf-raw=false`: отдельно из установленного комплекта и из распакованной копии 0.3.6. Оба процесса работали 3 секунды и сообщили `windivert initialized. capture is started.`; затем завершены только собственные тестовые PID. Фильтр не выбирал пакеты. Собственная служба до и после отсутствовала.

Полный прогон 0.3.7: 309 Python-тестов за 12,222 секунды, 305 успешно и 4 прежних пропуска из-за ограничения Windows на создание символических ссылок. В него входят регрессии новой диагностики; сохранён локальный журнал `dist/tests-0.3.7.log`.

Готовый EXE 0.3.7 проверен отдельно: в новой папке первоначально находился только EXE, после запуска доступно 28 стратегий. В тестовой копии после загрузки каталога временно убран `list-google.txt`. Запуск ALT11 через API вернул код выхода движка 1 и точную причину `No such file or directory`; тот же вывод сохранён в `data/last-startup-failure.json` с признаком завершённого чтения. Движок завершился до инициализации перехвата. Тестовый файл восстановлен; приложение закрылось с кодом 0, диагностический JSON сохранился. Собственная служба осталась отсутствующей.

Реальное обновление установленной копии 0.3.6 → 0.3.7 завершилось с кодом 0 за 3,1 секунды. Хеши 12 файлов настроек, отчётов, пользовательских списков и ACTIVE сохранились. Desktop-запуск подтвердил версию 0.3.7, 28 стратегий, набор 36 HTTP/TLS + 17 ping и ресурсы логотипа; закрытие через API завершило приложение с кодом 0. Собственная служба до и после отсутствовала. Перед обновлением работающей копии GUI не было, поэтому этот прогон не проверяет закрытие занятого elevated-окна.

Эти результаты проверяют сбор ошибки, но не устанавливают причину пользовательского кода 2. Ниже сохранены результаты прежних выпусков; их число тестов не относится к 0.3.7.

## Автоматические проверки до 0.3.6 включительно

- 298 Python-тестов: 294 успешно, 4 пропущены из-за отсутствия права Windows на создание символических ссылок. Проверки реальных junction и попытки изменения reparse point при распаковке прошли. Все 18 автономных JavaScript-тестов прошли в 0.3.4; код JavaScript в 0.3.5–0.3.6 не менялся.
- Добавлены проверки сборки и извлечения payload: явный список файлов, отсутствие пользовательских данных и зависимости от Git, детерминированность, хеши нативных компонентов, ошибки архива и путей, атомарная запись, сохранение существующих файлов, Unicode и параллельные запуски. Служебные режимы обновления и удаления службы не вызывают распаковку и Controller.
- В desktop-тестах проверены установка AppUserModelID до создания окна, обработка HRESULT, отсутствие вызова Windows API на другой платформе, путь значка в исходниках и PyInstaller, ошибка отсутствующего ресурса и передача ICO в pywebview. В тестах AppUserModelID процесса не изменяется: системный вызов подменён.
- Добавлены регрессии чтения длинной конфигурации службы: ограничение буфера SCM, допустимые ошибки fallback, типы и содержимое реестра, ownership/hash, запрет расширяемых переменных и предел длины UTF-16. Проверены остановка сразу после запуска, смена/отсутствие PID и переход из start_pending.
- 43 теста подготовки обновления: полный путь процесса и каталог комплекта, нестандартные порты, токен и Origin, отсутствие перенаправлений и прокси, ограниченные ответы и таймауты, ожидание файлов, закрытие native handles, CLI без Controller, повышения прав и скрытых диалогов. В 0.3.3 добавлены 12 регрессий SHA-256: совпадение только точного файла драйвера, несовпадение, ошибка чтения, другие блокировки, ранняя валидация суммы и повторная проверка содержимого во время ожидания.
- Проверена матрица Flowseal Standard: 36 HTTP/TLS-проверок и 17 ping-результатов, три режима HEAD, таймауты, отмена собственных процессов, русские и английские ping-ответы, отдельные счётчики. Список целей совпал с предоставленным `targets.txt` из комплекта 1.10.1, включая Quad9.
- Регрессии для прежних 5/5: неполная матрица, дубли, подмена режима, ошибки Googlevideo/Gateway, UNSUP и успешные ping не создают полный HTTP-успех. TLS-ошибки не скрываются одним словом schannel или кодом curl 35.
- Проверены новый рейтинг Standard, глобальная недоступность TLS 1.3, миграция старого автоподбора и сбой движка во время повторного подтверждения. Последний теперь отражается как ошибка в отчёте, а не успешные адреса.
- Импорт 22 исходных стратегий и генерация 6 вариантов. Имена параметров сверены со справкой поставленного бинарника; изменяемые значения сверены с исходниками движка.
- Передача 28 наборов аргументов через Windows subprocess с сохранением границ аргументов, включая пути с пробелами и кириллицей.
- Отмена перебора, исключение неполных результатов, смена сети, повторная проверка кандидата, восстановление предыдущего состояния и откат при ошибке сохранения.
- Ограничения локального API: адрес и источник запроса, токен для изменений, пути отчётов, маршруты управления службой.
- Пустые необязательные поля провайдера и города, миграция старого неподтверждённого профиля Инфолинка.
- Жизненный цикл desktop-окна, завершение через API, обработка ошибки WebView2, блокировка неподдерживаемых URL и открытие внешних HTTP(S)-ссылок в браузере.
- Логика установки, запуска, остановки, удаления и отката службы с подставным SCM-адаптером. Проверены владение службой, защищённая копия, хеши бинарников, пересборка путей аргументов и конфликт с прежней службой zapret.
- Контроллер не останавливает установленную службу при закрытии окна и блокирует сеансовый запуск и подбор, пока служба установлена.
- Перечисление процессов через Toolhelp32: размер структур Win64, Unicode, обработка ошибок и закрытие handles. В приложении больше нет периодического запуска PowerShell для этой проверки.

## Проверки в Windows

### Самостоятельный EXE в 0.3.6

- В новую пустую папку с пробелами в пути скопирован только `ZapretByNerd3n.exe`. Первый запуск выполнен из другой рабочей папки, без внешнего `bundle`, без Python в команде запуска и с отключённым автоподбором. Встроенный комплект извлечён без сетевой загрузки.
- Все 62 файла `bundle`, `profiles` и `licenses` совпали с размерами и SHA-256 встроенного manifest. Четыре нативных компонента дополнительно совпали с закреплёнными хешами. Профиль Инфолинка и уведомления о лицензиях присутствуют. В программе доступны 22 штатные и 6 дополнительных стратегий, матрица Standard содержит 36 HTTP/TLS и 17 ping-проверок.
- Первый запуск без окна подготовил API за 1,53 секунды. Затем проверен запуск отдельного desktop-окна; API стал доступен за 1,90 секунды. Оба экземпляра штатно завершились через API с кодом 0. Это замеры конкретного ПК, не гарантия времени запуска на других системах.
- Перед повторным запуском удалён один файл BAT-стратегии и изменены тестовые настройки, пользовательский список и ACTIVE-пакет. Отсутствующая стратегия восстановилась; все изменённые файлы и посторонний файл в папке остались побайтово прежними.
- Режим `--prepare-update` готового EXE завершился с кодом 0 без создания постоянного комплекта рядом с собой. Состояние собственной службы Windows до и после всех проверок не изменилось; на момент теста она отсутствовала.
- Проверка `winws --dry-run` в этой обычной пользовательской сессии потребовала повышения прав (Windows 740) ещё до запуска бинарника. UAC для проверки упаковки не запрашивался; запуск драйвера и эффективность обхода этим тестом не подтверждаются. Проверены наличие, целостность и импорт всех стратегий.
- Установленная копия обновлена с 0.3.5 до 0.3.6: код установщика 0, сохранены SHA-256 всех 12 проверенных пользовательских файлов. Готовое desktop-приложение сообщило версию 0.3.6, 28 стратегий и матрицу Standard 36/17; PNG, favicon и встроенный значок проверены. Выход через API завершился кодом 0; состояние службы не изменилось.

### Значок окна и панели задач в 0.3.5

- Новый пользовательский PNG с прозрачностью включён в интерфейс побайтово. ICO для окна, favicon, EXE и установщика получен преобразованием формата в размеры 16, 24, 32, 48, 64, 128 и 256 px; альфа-канал сохранён.
- Desktop-процесс задаёт `Nerd3n.Zapret` до загрузки pywebview и создания окна. Такой же AppUserModelID установлен у ярлыков. Значок окна назначается явно через `webview.start(icon=...)`, а ярлыки явно используют ресурс 0 установленного EXE.
- Реальное обновление 0.3.4 → 0.3.5 завершилось с кодом 0 за 2,91 секунды. Все 12 проверенных пользовательских файлов сохранили SHA-256. На начало этой проверки собственная служба отсутствовала; обновление и проверка окна не изменили это состояние.
- Установленный EXE 0.3.5 запущен в desktop-режиме без автоподбора: подтверждены версия, 28 стратегий, матрица 36/17, встроенный ресурс значка и совпадение PNG/favicon с исходными файлами. Штатный выход через API завершился кодом 0.
- Установленные ярлыки рабочего стола и меню «Пуск» проверены через свойства Shell: оба указывают на ресурс `ZapretByNerd3n.exe,0` и содержат AppUserModelID `Nerd3n.Zapret`.
- В отдельном запуске исходного desktop-окна прочитаны собственные WinForms-свойства: `ShowInTaskbar=True`, значок 32×32 и AppUserModelID `Nerd3n.Zapret`. Извлечённый bitmap совпал с кадром ICO пиксель-в-пиксель на светлом и тёмном фоне. ICO использует DIB-кадры: PNG-сжатые кадры давали некорректный результат в `Icon.ToBitmap()` .NET Framework. Окно штатно закрыто через API; состояние службы не изменилось. Внешний вид самой панели задач визуально не проверялся.

### Исправление Windows 1783 и логотип в 0.3.4

- На установленной ALT11 воспроизведена ошибка `QueryServiceConfigW`: команда ImagePath занимает 16 432 байта UTF-16, полный ответ требует 16 598 байт при ограничении API 8 КБ. Больший буфер не устраняет ошибку RPC 1783. Сама команда укладывается в предел запуска процесса Windows.
- Исходная прямая команда запуска сохранена. При известных ошибках чтения используется только защищённая запись собственной службы в реестре с проверкой ACL, владельца, формата, аккаунта и SHA-256. Состояние и PID по-прежнему читаются через SCM.
- Существующая служба ALT11 восстановлена и реально запущена с повышением прав. Подтверждены автоматический запуск, принадлежность приложению, состояние Running и отсутствие ошибки. После закрытия исходного приложения процесс службы продолжил работать с тем же PID.
- Для нового запуска добавлено трёхсекундное подтверждение устойчивого состояния: winws сообщает Running до разбора параметров, поэтому одного ответа SCM недостаточно для успешной установки.
- Пользовательский PNG включён в интерфейс без изменения изображения. ICO содержит размеры 16, 24, 32, 48, 64, 128 и 256 px; значок встроен в EXE и установщик. Проверены HTTP-маршруты, MIME и байты ресурсов. Логотип также проверен в браузере на странице обзора.
- Выполнено реальное обновление установленной копии 0.3.3 → 0.3.4: код установщика 0, время 2,95 секунды, перезагрузка не потребовалась. До обновления сохранена локальная резервная копия; SHA-256 всех 12 проверенных файлов настроек, отчётов, пользовательских списков и ACTIVE-пакетов после обновления совпали. Пользовательские данные в архив исходников не включены.
- Установленный EXE 0.3.4 запущен в desktop-режиме с отключённым автоподбором. Подтверждены версия, каталог комплекта, 28 стратегий, матрица Standard 36/17, работающая собственная служба и отсутствие сеансового движка. PNG и favicon совпали с исходными файлами; в PE проверен ресурс значка.
- Обновление, открытие и штатное закрытие приложения через API не изменили PID службы ALT11. Автозапуск подтверждён конфигурацией SCM; реальная перезагрузка Windows не выполнялась.

### Обновление 0.3.3 на установленной пользовательской копии

- После попытки обновления 0.3.2 GUI и winws завершились, но Windows оставила драйвер WinDivert в состоянии Running. Единственным заблокированным файлом был `bundle/bin/WinDivert64.sys` (Win32 32). Его SHA-256 совпал с файлом поставки.
- В 0.3.3 сумма берётся из реального файла при сборке установщика. Helper пропускает блокировку только совпадающего драйвера; Inno отдельно повторяет проверку суммы перед копированием. Драйвер исключён из общей wildcard-записи, чтобы она не пыталась перезаписать пропущенный файл.
- Произведено настоящее обновление 0.2.0 → 0.3.3 в `%LOCALAPPDATA%\ZapretByNerd3n`. Установщик с обычными правами завершился с кодом 0 за 3,11 секунды; журнал подтвердил пропуск совпавшего драйвера и отсутствие необходимости перезагрузки.
- До установки сохранена локальная резервная копия пользовательских данных. После установки все 9 проверенных файлов настроек, отчётов и выбранных payload сохранили прежние SHA-256. Личные данные и журнал конкретного компьютера в поставку не включены.
- Установленный EXE совпал с готовым EXE 0.3.3. Приложение запущено в desktop-режиме с отключённым для проверки автоподбором: API сообщил 0.3.3, правильный каталог комплекта, 28 стратегий и матрицу Standard 36/17. Выход через API завершился с кодом 0.
- WinDivert остался Running с прежним путём и прежним содержимым SYS. Принудительная остановка/удаление драйвера и вмешательство в чужие приложения не выполнялись.

### Обновление 0.3.2

- Причина прежнего сбоя подтверждена журналом реальной установки: повышенный EXE 0.2.0 оставался запущен, Restart Manager получал Permission Denied, затем DeleteFile завершался кодом 5.

- На отдельной копии реального EXE 0.2.0, запущенной без повышения прав на порту 17847, готовый helper 0.3.2 выполнил штатное завершение и дождался освобождения файлов за 3 секунды.

## Ранее измеренная нагрузка версии 0.3.0

Это замер предыдущей версии 0.3.0, а не повторный бенчмарк 0.3.1. Он выполнен на текущем Windows-ПК с 12 логическими процессорами, без запуска движка и подбора. После прогрева окно оставалось открытым 20 секунд; учитывались Python-приложение, загрузчик EXE и все дочерние процессы WebView2.

- Средний CPU: 0,085% общей мощности процессора, или около 1,02% одного логического ядра.
- Private Bytes: 283 МиБ на всё дерево процессов. Это выделенная собственная память, а не точный размер занятой физической RAM.
- Сумма Working Set: 467 МиБ. Общие страницы могут учитываться несколько раз, поэтому эта сумма завышает уникальную физическую память приложения.

Отдельный 20-секундный замер того же EXE с `--no-browser --no-auto-setup`, без WebView2, с запросом состояния каждые 2 секунды: CPU 0,0065% общей мощности, Private Bytes 28,3 МиБ, сумма Working Set 51,9 МиБ. В эту группу входит Python с контроллером и локальным сервером, а также загрузчик EXE.

Это один короткий замер конкретной сборки и WebView2, не гарантия для всех ПК. Перебор стратегий и работа самого winws в эти цифры не входят. После закрытия интерфейса его Python-сервер завершается; отдельно установленная служба движка остаётся работать.

## Что ещё требует проверки

На линии **Инфолинк, Щёлково** измерений пока нет. Ранее доступная среда определилась как другой оператор внешнего IP. Её успешные сетевые проверки при работающем стороннем winws не подтверждают ни подключение без обхода, ни эффективность наших стратегий.

Автоматические тесты используют подставные процессы и измерения там, где нужен перехват трафика. Они не доказывают обход DPI. Отдельные проверки WinDivert и ALT11 с фильтром `false` подтвердили инициализацию без обработки пакетов. Обычный запуск через новую оболочку с рабочими фильтрами, видео YouTube, QUIC, Discord WebSocket и голос требуют проверки на реальном подключении.

Восстановление и запуск существующей службы ALT11 с повышением прав проверены. Создание новой службы после исправления, запуск после перезагрузки и удаление службы ещё требуют реальной проверки. Обновление приложения проверено в пользовательской папке с заблокированным загруженным драйвером. Замена загруженного драйвера на отличающуюся версию и удаление приложения ещё требуют проверки. Для первого публичного выпуска рекомендуется статус pre-release.
