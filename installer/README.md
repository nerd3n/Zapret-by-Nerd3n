# Установщик zapret by nerd3n

`ZapretByNerd3n.iss` собирает установщик версии 0.3.7 для текущего пользователя Windows 10/11 x64.
ARM64 исключён: поставляемый драйвер WinDivert64.sys требует x64. По умолчанию
приложение устанавливается в `%LOCALAPPDATA%\ZapretByNerd3n`; папка показывается
перед установкой и может быть изменена. Создаётся ярлык в меню «Пуск», ярлык
на рабочем столе предлагается отдельно. Windows получает обычную запись
для удаления приложения.

После установки по умолчанию запускается `ZapretByNerd3n.exe --auto` с запросом
повышенных прав Windows. Отмена UAC оставляет установленное приложение:
его можно открыть позднее через ярлык. Ярлыки используют `--auto --elevate`.
Приложение само определяет, требуется ли первоначальный подбор, и не запускает
его повторно после завершения. При тихой установке приложение не запускается.
Установщик сам не создаёт службу. В приложении есть отдельная команда
«Установить с автозапуском»: она устанавливает выбранную стратегию как службу
`ZapretByNerd3n` с запуском при старте Windows. Комплект службы хранится отдельно
в защищённой папке Program Files, а не в пользовательском каталоге приложения.

В 0.3.4 служба сохраняет полную команду запуска EXE с аргументами стратегии.
Исправлено чтение длинной команды через `QueryServiceConfigW`, ответ которого
ограничен 8 КБ: только при RPC 1734/1783 либо ошибке 122 с запрошенным буфером
больше 8 КБ используется чтение реестра. Проверяются защищённый ACL ключа,
ownership marker со схемой 1 и хеш команды; запись службы при чтении не меняется.
Текущее состояние и PID всегда возвращает SCM. Существующую остановленную нашу
службу запускает кнопка **Запустить службу** с прежней стратегией. После перехода
в состояние «Работает» приложение 3 секунды проверяет устойчивость запуска.
Сам установщик не запускает службу и не меняет общий драйвер WinDivert.

Движок zapret, стратегии, списки и профиль `profiles/infolink-shchelkovo.json`
включены в установщик. Профиль по умолчанию пуст, JSON Инфолинка справочный.
Приложение использует папку `bundle` рядом с EXE;
выбирать или скачивать отдельный комплект для первого запуска не требуется.

В 0.3.6 тот же комплект также встроен в `ZapretByNerd3n.exe` как `payload.zip`.
Отдельный EXE можно скачать без установщика и положить в папку с правом записи.
При обычном запуске он извлекает рядом отсутствующие файлы `bundle`, `profiles`
и `licenses`; уже существующие файлы не перезаписывает. В `licenses` сохраняются
условия приложения и зависимостей, в `bundle/LICENSE.txt` — лицензия комплекта.
Для извлечения интернет не требуется. Это один файл для распространения;
после первого запуска рабочие файлы остаются на диске рядом с EXE.

Замена только EXE обновляет оболочку и сохраняет прежний `bundle`. Обновление
штатного движка и списков с сохранением пользовательских файлов выполняет
установщик. Уже установленная служба использует свою защищённую копию и не
зависит от распаковки рядом с EXE.

Перед копированием файлов установщик извлекает новый EXE во временную папку
и запускает `--prepare-update <папка установки>`. Режим находит локальный API
процесса с совпадающим полным путём EXE, сверяет папку комплекта и запрашивает
штатное закрытие. Это работает с API 0.2.0 и нестандартным портом. Ожидание
освобождения EXE и заменяемых файлов движка ограничено 60 секундами. Если файлы
остаются заняты или доступ запрещён, `PrepareToInstall` останавливает установку
до замены файлов. Принудительного завершения процессов и изменения служб здесь нет.
Ветви `--prepare-update` и `--remove-service` выполняются до извлечения встроенного
комплекта: запуск временного EXE установщиком не создаёт рядом `bundle`, `profiles`
или `licenses` и не открывает интерфейс.

Исключение 0.3.3 касается только `bundle/bin/WinDivert64.sys`: если установленный
файл совпадает по SHA-256 с драйвером в пакете, helper не требует его освобождения,
а Inno пропускает копирование. Ожидаемый SHA-256 вычисляется из файла поставки
при компиляции установщика через ISPP `GetSHA256OfFile`; проверка выполняется
перед использованием исключения. Загруженный идентичный драйвер остаётся на месте.
Ошибка чтения или несовпадение хеша не разрешают пропуск. Остальные EXE, DLL и SYS
по-прежнему должны быть доступны для замены. Общая служба WinDivert не останавливается
и не удаляется: её могут использовать другие приложения, даже когда `winws` уже закрыт.
Это исправляет отказ 0.3.2 на сохраняющейся блокировке идентичного драйвера;
при замене другой версии занятого драйвера может понадобиться перезагрузка Windows.

При повторной установке сохраняются пользовательские списки, результаты,
настройки и выбранные `ACTIVE_*.bin`. Удаление убирает установленные файлы
программы и ярлыки; созданные пользователем данные остаются. Перед удалением
нужно завершить приложение. Если наша служба установлена, деинсталлятор запускает
`ZapretByNerd3n.exe --remove-service` с запросом UAC и ждёт завершения. Отказ UAC
или оставшаяся запись службы (включая чужую службу с тем же именем) прерывают удаление программы. CLI не
запускает интерфейс, не создаёт Controller и не управляет чужими службами.

Окно использует pywebview и Microsoft Edge WebView2 Runtime. Сам Runtime должен
быть установлен в Windows; его можно получить [на сайте Microsoft](https://developer.microsoft.com/en-us/microsoft-edge/webview2/).
Python и библиотеки оболочки включены в EXE.

В 0.3.7 улучшена диагностика немедленного завершения сеансового `winws`:
последний вывод процесса включается в ошибку, а сведения сохраняются в
`data/last-startup-failure.json` рядом с EXE. Этот файл относится к пользовательским
данным и не должен попадать в установщик или встроенный payload. Выпуск не заявляет
исправление сообщённого кода 2: его причина пока не воспроизведена.

## Сборка

Из корня проекта сначала соберите EXE helper-скриптом, используя подготовленное
виртуальное окружение с PyInstaller и зависимостями из `requirements.txt`:

```powershell
.\tools\build-desktop.ps1 -BuildPython .\.build-env\Scripts\python.exe
```

Он создаёт `build/desktop/payload.zip`, встраивает комплект и интерфейс в EXE,
сохраняет результат с SHA-256 в `dist` и копирует EXE в корень проекта для Inno.
Каталог результата можно изменить через `-OutputDir`. Прежняя ручная команда
PyInstaller с включением только `web` не подходит для отдельного EXE 0.3.6.
Состав релиза готовьте из чистого снимка, без пользовательских списков и данных:
порядок описан в [docs/RELEASING.md](../docs/RELEASING.md).

Для Inno `ZapretByNerd3n.exe` должен находиться рядом с `bundle`, `profiles`, `README.md`,
`LICENSE`, `THIRD_PARTY.md`, `GSAP-LICENSE.txt`, `PYTHON-LICENSE.txt`,
`DESKTOP-LICENSES.txt`, `VERIFICATION.md`, `assets/app.ico` и папкой `docs` с инструкцией по выпуску.
Затем выполните PowerShell-команду:

```powershell
.\installer\build-installer.ps1 -CompilerPath 'C:\Tools\Inno Setup\ISCC.exe'
```

Дополнительные параметры: `-AppDir`, `-OutputDir`, `-Version`. Можно также
задать путь к компилятору переменной `ZAPRET_ISCC`. Результат по умолчанию:
`dist\Zapret-by-nerd3n-Setup.exe` и контрольная сумма `.sha256`. Данные тестирования,
настройки сборщика и Python-исходники в установщик не включаются. Веб-интерфейс
и payload должны быть встроены в EXE при его сборке.

Иконка установщика берётся из `assets/app.ico` подготовленной папки `-AppDir`.
Helper сборки приложения передаёт PyInstaller `--icon assets/app.ico`; HTML-логотип
и favicon входят в папку `web` и встраиваются вместе с ней. Начиная с 0.3.5 используется
обновлённое изображение логотипа. Окно pywebview получает локальную ICO-иконку явно,
а процесс приложения — `AppUserModelID` `Nerd3n.Zapret`.

У записей `[Icons]` явно заданы `IconFilename: "{app}\ZapretByNerd3n.exe"`
и `IconIndex: 0`; ярлыки запуска приложения сохраняют `AppUserModelID: "Nerd3n.Zapret"`.
Эти параметры задают значки окна и ярлыков. Закрепление на панели задач пользователь
выполняет через Windows самостоятельно.

MIT-лицензия приложения принадлежит nerd3n. Лицензии движка и зависимостей
сохраняются отдельно. Исходный код приложения поставляется отдельным ZIP-архивом;
этот скрипт собирает установщик готовых бинарников.

Используется официальный Inno Setup 6.7.3. Его установочный файл
[из официального релиза](https://github.com/jrsoftware/issrc/releases/tag/is-6_7_3)
имеет SHA-256 `9c73c3bae7ed48d44112a0f48e66742c00090bdb5bef71d9d3c056c66e97b732`;
цифровая подпись проверена, издатель Pyrsys B.V. Режим `/PORTABLE=1`
описан в [исходниках Inno Setup](https://github.com/jrsoftware/issrc/blob/is-6_7_3/isportable.iss).

Сборка установщика не выполняет установку приложения и не запускает `winws`.
Готовый установщик этого проекта не имеет коммерческой цифровой подписи.
